## Content

**Context.** The toolkit's always-on text says durable memory lives in tracked
files under `docs/_internal/`; `link` writes that path into `SCIO:GITIGNORE`
(`link.sh:278`) and `docs-layout` warns when it is absent from the ignore list.
The mandated location is guaranteed untracked, so by the instruction's own words
it counts as no record. A 24-project survey found: 10 projects with no
`docs/_internal/` at all; two that independently made it a nested git repo (126
and 210 commits, 195 and 708 tracked files, **no remote on either**);
`handoffs/` shipped empty everywhere while real handoffs went to `sessions/`;
ten spellings of "handoff"; a root `_scratch/` that exists nowhere despite being
called the only sanctioned throwaway zone; and one tree at 568 MB because a
virtualenv lives in it. Full evidence:
`docs/_internal/research/2026-08-20-internal-skeleton/`.

**Decision.** Record all of:

1. **Memory mirrors the analysis.** `docs/_internal/<stage-stem>/` keyed to
   `02_analysis/stages/NN_<stem>.*`, with `_project/` for memory that spans or
   precedes stages. The key is the stage number the human already reasons in —
   no metadata to maintain. Explicitly **no** mirror of `02_analysis/helpers/`:
   a helper serves several stages, so its rationale files with the consuming
   stage.
2. **Two durable forms.** `reasoning/<topic>.md` and `session.md`, the latter
   updated in place with git history as the archive. This is what retires the
   dated-pile problem instead of standardising it.

   **OPEN — owner decision, do not resolve unilaterally.** "Two forms only"
   contradicts the fleet's best-working practice and the toolkit's own. 14782-DM
   carries `docs/_internal/plans/2026-08-14_consensus-migration/` — a 93-line
   `00_STATE.md` (worker/path table, `.pth` finding, the dot-directory glob
   trap, test counts, the GitHub-only tag, open owner decisions) plus six
   numbered phase files. That is the most functional memory record found in the
   survey. This toolkit ships `templates/plan/{00_INDEX,NN_slug}.md.template`
   and its own `docs/_internal/plans/` is where this very plan lives.

   So a **plan is a third durable form**, and the ADR should say so rather than
   pretend otherwise. Proposed resolution for the owner to accept or replace:
   a plan lives at `_project/plans/<date-slug>/` because it spans stages;
   `00_STATE.md` **is** that plan's `session.md` under another name, so pick one
   spelling and keep it; and like everything else it is **created with content,
   never scaffolded** — which is fully consistent with phase 03, since phase 03
   deletes `plans/` as a *pre-created empty default*, not as a place a real plan
   may go.
3. **Scratch is not memory.** It is disposable work. No sanctioned location is
   named, because naming one that agents do not use is how `_scratch/` failed.
4. **Never scaffold empty.** A directory arrives with its first real file.
   Structure propagates when the tree holds an authentic instance whose form can
   be copied; `.gitkeep` is an unsupported claim and agents discount it.
5. **No new hook** — not Claude, not Codex, not git `pre-commit`. Enforcement is
   `scio lint --check internal-memory`, opt-in, harness-blind because it reads
   the tree. Record that Codex *does* have a full hook surface
   (`PreToolUse`/`Stop`/`SessionStart`, `~/.codex/hooks.json`, trust by
   definition hash) and that using it was **rejected** because it would require
   a project `.codex/` where none exists in any of 24 projects, duplicating a
   Claude-shaped mechanism. A `pre-commit` calling lint stays available as a
   later escalation if evidence shows agents skip lint.
6. **Topology: nested repo in place, plus a parent-tracked pointer.**
   `docs/_internal/` becomes its own git repo; the parent already ignores it, so
   nesting needs no wiring. `docs/internal-memory.md` is **tracked by the
   parent** and names where the memory lives — that is what makes a nested repo
   declared rather than hidden. Rejected: submodule (durability would depend on
   pin bumps, and 20 of 24 copies are currently stale at one pin), and
   parent-tracked memory (agent churn floods the human log; the publish hazard
   returns).
7. **The seam.** scio owns path grammar, examples, always-on router text and
   lint predicates. dev-env owns user-global habits. Test: *follows the repo →
   scio; follows the human → dev-env.* Corollary: dev-env may name a path for a
   tool, never for an agent.

**Consequences.** Name what becomes deletable (phases 01/03) and state the
migration: no bulk-add of the 8,317 existing files, no relocation exercise,
existing memory handled opportunistically when a project next becomes active,
and no `docs/_internal/` created anywhere — absence is the majority state and
legitimate.

Also record the **review question** this whole exercise produced, because it
generalises past memory: *for every claim the toolkit makes, what enforces it,
and can that thing actually deliver?* Four defects found on one day were all the
same shape — an instruction naming something the mechanism does not guarantee.

**Blocks:** nothing. **Reversible:** yes; the deletions are recoverable from
history and no data is destroyed.
